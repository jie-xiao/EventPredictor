## HIGH

### H1. SSE response missing explicit CORS headers

**File:** `app/api/routes/sse.py:141-149`

```python
response = StreamingResponse(
    _sse_generator(request, queue),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",
    },
)
```

No `Access-Control-Allow-Origin` in the response headers. The global CORS middleware may not apply correctly to StreamingResponse — the browser's EventSource checks headers only at connection time.

**Impact:** EventSource connections may be blocked by CORS when frontend is on a different origin.

**Fix:** Add `"Access-Control-Allow-Origin": "*"` or use the configured origins to the response headers.

### H2. useSSE hook never passes auth token

**File:** `frontend/src/hooks/useSSE.ts:94-97`

```typescript
  // TODO: 可以改用 query param 方式传 token
```

The `_token` parameter is prefixed with underscore (unused) and never appended to the EventSource URL.

**Impact:** SSE connections always reach the server as anonymous. User-targeted notifications cannot be delivered.

**Fix:** Append token as query parameter:

```typescript
const url = token
  ? `${API_BASE_URL}/api/v1/stream/events?token=${encodeURIComponent(token)}`
  : `${API_BASE_URL}/api/v1/stream/events`;
```

And update `sse.py` to read token from query params.

### H3. Notification create commits entire session

**File:** `app/services/notification_service.py:31-43`

```python
async def create_notification(self, session, ...):
    notification = Notification(...)
    session.add(notification)
    await session.commit()   # commits ALL pending changes in this session
```

If the caller has other dirty state in the same session, it will be committed prematurely.

**Impact:** Medium. Depends on how callers manage sessions.

**Recommendation:** Document this behavior or keep it as-is (consistent with existing codebase patterns).

## MEDIUM

### M1. SSEConnectionManager disconnect has side effects on broadcast queue-full

**File:** `app/api/routes/sse.py:66-76`

```python
async def broadcast(self, event_type, data):
    ...
    for cid in disconnected:
        self.disconnect(cid)  # removes from _user_connections too
```

When a single client's queue is full, `disconnect` is called, which also removes the client from `_user_connections`. If the same user has other active connections and this was the last client_id in that user's set, the entire user entry is deleted, orphaning the remaining connections from user-targeted sends.

**Impact:** Low probability (requires same-user multi-connection + queue full).

**Fix:** In `broadcast`, clean up the full queue independently instead of calling `disconnect`:

```python
for cid in disconnected:
    q = self._connections.pop(cid, None)
    if q:
        q.put_nowait(None)
    for uid, cids in self._user_connections.items():
        cids.discard(cid)
```

### M2. Notification panel lacks pagination

**File:** `frontend/src/components/NotificationCenter.tsx:181-219`

All notifications are rendered in a single scrollable container. API limits to 30, so current DOM impact is minimal, but there is no "load more" mechanism if the user needs older notifications.

**Impact:** Low (30 items is fine). Long-term, add pagination.

### M3. data_service.py ambiguous dict format fallback

**File:** `app/services/data_service.py:81-84`

```python
else:
    self._events = list(data.values())  # fallback
```

If JSON has unexpected structure like `{"metadata": {...}, "events": "not_a_list"}`, the metadata object gets treated as an event, causing downstream type errors.

**Fix:** Filter values:

```python
self._events = [v for v in data.values() if isinstance(v, dict) and "title" in v]
```
