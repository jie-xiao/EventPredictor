## 新发现的问题

### N1. sklearn 依赖缺失（CRITICAL）

**文件：** `app/services/calibration_service.py:5-6`

```python
from sklearn.linear_model import LogisticRegression
import numpy as np
```

`scikit-learn` 未在 `requirements.txt` 中声明。`calibration_service.py` 由 `calibration.py` 路由文件导入，路由文件在 `main.py` 中注册。

**影响：** 如果运行环境中未安装 scikit-learn，应用启动时就会抛出 `ModuleNotFoundError`。

**修复：**
1. 将 sklearn 加入 `requirements.txt`：`scikit-learn>=1.3.0`
2. 或将 sklearn import 改为延迟加载（lazy import），放在 `calibrate` 方法内部的 try/except 中

### N2. numpy import 也是模块级硬依赖（MEDIUM）

**文件：** `app/services/calibration_service.py:6`

虽然 `numpy` 在 `requirements.txt` 中，但 `calibration_service.py` 在模块级别导入它，而它只在 `calibrate()` 方法中使用。如果 calibration_service 被导入但从未调用 calibrate，numpy 仍会被加载。

**建议：** 将 sklearn 和 numpy 的 import 都移到 `calibrate()` 方法内部。

### N3. useSSE.ts 存在过时注释（LOW）

**文件：** `frontend/src/hooks/useSSE.ts:99-102`

```typescript
  // 如果有 token，SSE 不支持自定义 header，
  // EventSource 的认证通常通过 query param 或 cookie
  // 这里不做 token 注入，服务端从 header 读取（SSE 连接建立时无法设置 header）
  // TODO: 可以改用 query param 方式传 token
```

此注释与第 41-44 行的实际代码矛盾——token 已经通过 query param 传递了。

**修复：** 删除或更新注释。

## 代码质量总评

### 新增模块（backtest / calibration / outcome_tracker）

**优点：**
- 文件职责单一，边界清晰
- 遵循现有项目模式（global singleton + async）
- 数据库访问使用延迟导入（lazy import），避免循环依赖
- 错误处理保守（try/except 包裹，失败时返回安全默认值）
- 回测指标计算正确（Brier Score, AUC, Sharpe Ratio）

**可改进：**
- `backtest_service._compute_auc` 中的梯形积分需要验证边界情况（单类别时的 early return 已处理）
- `outcome_tracker._resolve_expired` 中，将过期预测标记为 "partial" 是合理的默认行为，但应记录日志

### 路由层（backtest.py / calibration.py）

**优点：**
- 薄路由层，直接委托给 service
- 统一的错误处理模式

**可改进：**
- backtest.py 在路由函数内部延迟导入 SQLAlchemy 模块——可以提取为模块级导入（与项目其他路由风格一致）
